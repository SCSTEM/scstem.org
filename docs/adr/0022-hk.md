# 0022 — hk runs lint and format for every entry point

- **Status:** accepted
- **Date:** 2026-09-26
- **Amends:** [0021](0021-ci-shape.md)

## Context

Nothing ran on commit, so a formatting slip or a lint error surfaced only when CI reported it.
Prettier and ESLint were invoked four different ways: the `lint`, `lint:fix`, `fmt`, and
`fmt:check` scripts, the CI steps (with their own annotation flags), and the Claude Code edit
hook, each with its own flags.

## Decision

- **hk** (pinned in `mise.toml`, so `mise install` provides it and CI installs it beside node and
  pnpm) owns the Prettier and ESLint invocations, in `hk.pkl`. Its top-level `steps` generate
  the `pre-commit`, `check`, and `fix` hooks from the one definition.
- Every entry point runs those steps:
  - the git pre-commit hook, which fixes the staged files, restages them, and stashes unstaged
    work meanwhile. mise's `postinstall` hook runs `hk install --mise`, so every `mise install`
    outside CI installs it;
  - `pnpm lint` (`hk check --all`) and `pnpm fix` (`hk fix --all`), and so `pnpm check`;
  - CI's Check job, as `hk check --all --no-fail-fast`;
  - `.claude/hooks/format-lint.sh`, as `hk fix` on the edited file.
- The ESLint step passes `--format gha` everywhere. The formatter writes workflow-command
  annotations when `GITHUB_ACTIONS` is set and stylish output otherwise, and hk prints a failing
  step's output unprefixed, so CI annotations come from the same command a commit runs.
- Both steps set `batch = false`: one process per step. Batching split ESLint into eleven
  processes, each building the TypeScript program again: 62 s of CPU for `hk check --all`,
  against 12 s unbatched.
- hk is pinned at 2.0.1, the newest release mise's seven-day `minimum_release_age` admits; the
  Pkl imports in `hk.pkl` name the same version and move with it.

## Alternatives considered

- **lefthook, husky with lint-staged.** Hook runners only: CI and the edit hook would keep their
  own invocations, which is the duplication this removes.
- **Package scripts as the shared layer, called from hk.** `fmt:check` is `prettier --check .`;
  passing it staged files would check them and the whole tree. The scripts would have to become
  file-list-taking wrappers, a second place for the same flags.
- **Keeping per-file Prettier annotations in CI.** They carried no position, only the file name,
  which hk already prints with the command that fixes it.

## Consequences

- Git hooks live in each clone's local config, which is why `mise install` installs this one; a
  clone that has never run `mise install` has no hook. The launcher runs hk through `mise x`, so
  Git needs mise on its `PATH`.
- A commit whose staged files fail an unfixable ESLint rule is refused; `HK=0 git commit` skips
  the hook when that is intended.
- knip does not read `hk.pkl`: `eslint-formatter-gha` is in its `ignoreDependencies` and `hk` in
  `ignoreBinaries`.
- Typecheck and knip stay out of the hook; both read the whole program and belong to
  `pnpm check` and CI.
